# 製品ゴール

> CLAUDE.md から参照される。研究上の原則（docs/research/）と矛盾する場合はここで調停する。

## ゴール

**Claude Code で大規模開発を回し、最終的に一般ユーザーが遊べる製品にする。**

研究的な正しさ（決定論・再現性・検証可能性）は目的ではなく土台である。
ゲームの中核体験「文明を観察する → 任意時点に巻き戻す → 介入する → 分岐した歴史を並べて比較する」は、
カーネルが bit 単位で再現可能であり、スナップショットと台帳から任意の時点を復元できることで初めて成立する。
したがって研究用の要件（ADR-0002〜0004, 0008）は製品要件として引き続き守る。

## 最初の遊べるマイルストーン: Toy 1

ブラウザだけで完結する、最小の「巻き戻し・分岐」体験。

| 要素 | 内容 |
|---|---|
| 観察 | 文明（Phase 1 カーネルの世界）がブラウザ内で動き、個体・食料・人口推移を見られる |
| 巻き戻し | タイムラインをドラッグして任意の tick に戻れる（スナップショット + 再生） |
| 介入 | その時点で条件を変える: 干ばつ（再生量を下げる）、資源量の変更、個体の追加/除去 など |
| 分岐 | 介入後の世界を元の歴史と**並べて**再生し、人口・資源・寿命などの指標を比較できる |
| 検証性 | 同じ操作をもう一度行うと同じ分岐が得られる（決定論）。分岐の差分は数値で示す |

Toy 1 の受け入れ基準（Phase 2 の完了条件を兼ねる。詳細は ADR-0010）:

1. ユーザーがブラウザを開き、上の 4 操作を 5 分以内に自力で体験できる。
2. 2 つの分岐世界が同一画面に並び、少なくとも人口カーブと食料総量が比較できる。
3. 同じ介入を同じ tick で 2 回行うと、2 本の分岐の状態ハッシュが一致する。
4. サーバーなし（静的ファイルのみ）で動く。

## 原則

1. **世界の事実はプログラムが決める。** 誰が生まれ、何を採り、誰が死んだかは `simulation-core` の決定論的遷移だけが決める。
2. **LLM を使う場合は「歴史の語り」（演出）に限定する。** 年代記の文章化、出来事の要約、名前付けなど。
   LLM の出力は状態遷移・行動決定・制度の成立判定に一切関与しない。語りが事実と食い違えば語りが間違っている。
3. **各 Phase の完了条件には、ブラウザで見て確認できるデモを必ず含める。** コードとテストだけで「完了」にしない。
4. **研究の主張と製品の演出を混同しない。** 画面に「所有権が生まれた」と表示する場合、それは事前登録した指標の計算結果であり、LLM の解釈ではない。

## Phase ごとのブラウザデモ（完了条件の一部）

| Phase | デモ |
|---|---|
| 1 | トレースビューア: 1,000 体の世界の再生、個体クリック、人口推移（済） |
| 2 | **Toy 1**: ブラウザ内実行、巻き戻し、介入、分岐の並列比較（済 2026-10-17: https://two-three-co.github.io/civilization-zero/ ） |
| 3 | 個体の記憶・通信・交渉が可視化され、学習方策と固定方策の世界を並べて比較できる（済 2026-10-17: 同 URL の個体インスペクタ、`?policy=mixed&seed=23` の交渉スレッド、「Compare: fixed vs learning」。ADR-0013 の完了判定） |
| 4 | 制度エクスプローラ: 提案・合意・違反・制裁の履歴を時系列で追える |
| 5 | 実験ダッシュボード: 複数シード・条件格子の結果分布を見て、介入効果を比較できる |
| 6 | 認知構造の系統樹と、世代をまたぐ変化の可視化 |

## 技術方針（製品観点）

- ブラウザ内実行を第一候補にする（`simulation-core` を WASM 化）。サーバーは「共有・保存」が必要になるまで置かない。検討と計測は ADR-0009。
- UI は Phase 2 で React + Vite + PixiJS/Canvas に移行する（ADR-0007 の予定どおり）。
- 性能目標（Toy 1）: 1,000〜2,000 体の世界を、ブラウザ内で実時間 60 tick/s 以上で進められること。計測で確認する。
