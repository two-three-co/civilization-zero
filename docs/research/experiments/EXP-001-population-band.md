# EXP-001: 出生・寿命導入後の個体数は定常帯域に収束するか（健全性チェック）

- 実施日: 2026-10-17 · カーネル: `simulation-core` 0.1.0（ADR-0008 適用後、ゴールデンハッシュ `0xd1890b311b92678e`）
- 機種: Apple M1, rustc 1.99.1, release build
- 種別: **健全性チェック**。研究仮説 H1〜H5 の検証ではない。Forager は設計者が書いた方策なので、その振る舞いは創発の証拠にならない。

## 目的

Phase 1 の受け入れ基準「Forager で複数シード（最低 10）を実行し、個体数が一定帯域に収束することを計測で示す」を満たす。
Random 方策は帰無モデルとして同条件で実行し、全滅しても結果を記録する。

## 事前に決めた判定基準

（sweep の実行前に決めた基準。本文書の記載は実行後。）

1. 10 シードすべてで絶滅しない。
2. 各シードで、後半 50%（tick 10,001〜20,000）の個体数について `max / min <= 1.5`（中点から ±20% 以内）。
3. シード間で、後半平均の変動係数 CV `<= 0.15`。

## 条件

- `WorldConfig::default()`（128×128、初期 1,000 体、資源パッチ 23 個 = CLI の `side²/700`、`birth_threshold` 80,000、`child_energy` 40,000、`max_age` 3,000、突然変異 OFF）
- 20,000 tick、seed 0〜9、方策は Forager のみ / Random のみ
- 計測コマンド:

```bash
cargo run --release -p cz-cli -- sweep --seeds 10 --ticks 20000 --policy forager --window 50 --sample 100 --out out/forager
```

```bash
cargo run --release -p cz-cli -- sweep --seeds 10 --ticks 20000 --policy random --window 50 --sample 100 --out out/random
```

## 判定

基準 1〜3 をすべて満たす。**Phase 1 の受け入れ基準は達成。**

## 限界・注意

- 帯域の位置（約 1,300 体）は再生量・代謝・出生閾値といった設計者のパラメータで決まる。「1,300 という数」に意味はない。
- 検証したのは既定設定 1 条件のみ。パラメータ格子での挙動（例: 再生量を半分にしたときの帯域や絶滅確率）は未計測。
- 20,000 tick は `max_age` 3,000 の約 6.7 倍で、世代交代は起きているが長期の遺伝的ドリフトは扱えない（突然変異 OFF なので本実験では問題にならない）。
- 1 シード内の変動（±6%）がどこから来るか（空間的な資源の枯渇・再生の波か、出生のパルスか）は分析していない。

## 注記（2026-10-17、ADR-0013 3-2 以降）

Random 方策は 3-2 で社会行動（`Transfer` / `Store` / `Harm`）も一様に抽選するようになった。上の Random の数値は 3-2 以前の
7 行動版のもの。3-2 以降の Random は加害の試行コスト（既定 2,000）で急速に消耗し、1,000 体が tick 100 で約 200 体、tick 300 で絶滅する
（`cz run --policy random`、seed 42）。Forager の結果は影響を受けない（ゴールデン不変）。
3-3 で Random は `Signal(Say)` も抽選するようになった（11 行動）ので軌跡はさらに変わる（seed 42: tick 100 で 223 体、tick 200 で 6 体）。Forager は不変。
3-4 で Random は `Propose` / `Accept` / `Reject` も抽選する（14 行動）。加害を引く確率が 1/11 → 1/14 に下がった分だけ消耗が遅く、seed 42 では tick 100 で 362 体、tick 200 で 2 体、tick 300 で絶滅（最初の 100 tick に提案 3,246、受諾 1,196、拒否 1,203 が届いた）。Forager は不変（ゴールデン `0x658ee873d1866501`）。
