# EXP-002: 学習方策（Reflex / Learner）は固定方策（Forager）の個体数帯域に届くか（健全性チェック、事前登録）

- 仕様の登録日: 2026-10-17（実行前にこの文書だけをコミットする。結果は実行後に「結果」節へ追記し、仕様の節は書き換えない）
- カーネル: `simulation-core` 0.1.0（ADR-0013 3-7 適用後、Forager のゴールデン `0x658ee873d1866501`）。実行に使うバイナリのコミットは結果節に記す
- 機種: Apple M1（8 コア、16 GB）, rustc 1.99.1, release build
- 種別: **健全性チェック**（ADR-0013 D9、完了条件 3）。研究仮説 H1〜H5 の検証ではない。Forager は設計者が書いた方策、Reflex / Learner も設計者が置いた特徴・状態・報酬の上で動くので、ここで何が出ても創発の証拠にはならない

## 問い

ADR-0013 D9: **学習する方策は、設計者が書いた Forager の個体数帯域に届くか。** 学習が物理の中で「効く」こと（学習者が生き残り、帯域に収束し、Q 表や重みが白紙から動く）を 10 シードで確認する。

仮説表（docs/research/HYPOTHESES.md）との関係: H1〜H5 のどれも直接は検証しない。H1（所有権相当の規範）と Phase 4 の前提「学習者が生き残り、社会行動（移転・加害・発信）が台帳に載る」を満たすかの準備計測であり、RISKS.md R6（加害の退化均衡、報酬ハッキング）の最初の計測でもある。

## 事前に決める指標

すべて `<腕>_summary.csv`（シードごと 1 行）から読む。「窓」は後半 50% の 10,000 tick。「個体·tick」は窓の各 tick の開始時の生存数の総和（= 決定の総数）。

| # | 指標 | 列 | 定義 |
|---|---|---|---|
| M1 | 絶滅 | `extinct_at` | 生存数が 0 になった最初の tick（なければ `-`）。腕ごとに絶滅したシード数 |
| M2 | 帯域 | `win_mean` / `win_min` / `win_max` / `win_max_over_min` | 窓の生存数の平均・最小・最大・最大/最小。シード間の平均・標準偏差（母集団）・CV |
| M3 | 摂取量/体 | `win_consumed_per_agent_tick` | 窓で消費された食料単位 / 個体·tick（1 単位 = 4,000 ミリエネルギー） |
| M4 | 社会行動の件数 | `win_transfers_per_tick` / `win_harms_per_tick` / `win_signals_per_tick` / `win_proposals_per_tick` / `win_acceptances_per_tick` / `win_rejections_per_tick` | 窓で**成立した**移転・加害・発信（Say）・届いた提案・受諾・拒否の件数 / tick（台帳と同じ定義。失敗した試行は入らない） |
| M5 | 死因構成 | `win_deaths_starvation` / `win_deaths_old_age` / `win_deaths_violence` | 窓の死亡数（原因別）と、その比 |
| M6 | 行動構成 | `win_act_move` … `win_act_signal`（8 列） | 窓の決定のうち各種類が占める割合（成功・失敗を問わない。8 列の和 = 1） |
| M7 | Learner の表 | `q_abs_mean` / `q_delta_window` / `<腕>_qpolicy.csv` | 終了時の生存学習者の Q の \|値\| の平均（報酬単位 = 100 ミリエネルギー、固定小数点 16 を割った値）。窓の始め（tick 10,000 の開始時）と終わり（tick 20,000）の**集団平均 Q 表**の差の \|値\| の平均（同単位）。行ごとに「終了時の生存学習者のうち各種類を貪欲に選ぶ個体数」（同点は `tie`） |
| M8 | Reflex の表 | `reflex_weight_drift` / `hunger_permille_mean` | 終了時の生存個体の \|w − w₀\| の平均（w₀ = Forager 等価の初期重み、1.0 = 1024 単位）。`hunger_permille` の平均（突然変異が動かす唯一のスカラー） |
| M9 | 実行時間 | `ticks_per_s`、`RUN.log` の壁時計時間 | シードごとの tick/s（`World::step` 以外も含む）と腕ごとの合計時間 |

探索の床（Learner の判定に使う定数）: ε = 50‰ の探索は 8 種類を一様に選ぶので、どの種類も決定の **0.625%**（= 0.05 / 8）は探索で選ばれる。Transfer / Harm は隣接個体がいなければ Rest に化ける（アクチュエータ、3-6）ので、成立件数はこれ以下になる。「床の 2 倍」= 決定割合 **0.0125** を「貪欲には選ばれていない」の目安にする。

## 既知の限界（事前）

- **単一設定**。既定世界 1 条件、ε 1 値、突然変異幅 1 値、グリッド 1 サイズ。パラメータ格子は扱わない（EXP-001 と同じ限界）。
- **報酬は自己のエネルギーだけ**（ADR-0013 D6）。移転は損なので分かち合いは出なくて当然、出ないことは失敗ではない（Phase 4 の制度が「割に合う」条件を作る）。死に終端の負の報酬はない（D6）ので、学習者は「死を避ける」ことを直接は学ばず、餓死は −5 の連続と Consume の不発としてしか学ばれない。
- **Signal は無料**（`signal_cost` 0）で Rest と報酬で区別がつかない。発信件数は通信の学習の証拠にならない（P5f）。記号の意味も進化・学習しない（3-6: 聞いた記号の反復）。
- **交渉（Propose / Accept / Reject）は Reflex / Learner の行動集合にない**（8 種類、Signal = Say）。F / X / L の腕で `win_proposals_per_tick` 等が 0 なのは構造上の帰結であり、Random だけがこれらを出す。
- **個体数は適応度ではない**。帯域が高いのは 1 個体あたりの消費が少ない（休む、歩かない）結果でもあり得るので、M3（摂取量/体）と M6（行動構成）と合わせて読む。Forager は設計者の参照であって最適解ではない。
- **20,000 tick は進化には短い**（`max_age` の 6.7 倍）。X1-50k で 2.5 倍にするが、それでも収束の保証はない。
- **Violence 死の由来**。Learner の加害は探索（ε）由来が主と予測するが、カーネルは加害が探索か貪欲かを記録しないので、`win_act_harm` と床の比較で間接に判定する。
- **統計**。10 シードの記述統計（平均・sd・CV・対の勝敗数）のみ。信頼区間・検定は出さない。
- 実行時間は `cz sweep` の総時間で、`World::step` 以外（系列の書き出し、表の統計）を含む。

### 読み（事後の解釈。事前登録の判定ではない）

1. **学習方策は Forager の帯域に届き、上回った。** Reflex（突然変異 ON）1572、Learner 32 行 1623、Forager 1312。ADR D9 は「Learner ≤ Forager」と予測していたが、10 シードすべてで逆だった。これは「学習が効く」健全性チェックとしては合格だが、個体数が多いことを「賢い」と読まないこと: Forager は設計者が置いた一つの規則集であって最適解ではない（R7）。
2. **個体数が増える機構は「1 体が節約する」より「集団が刈り取る」。** 1 体あたりの摂取は F 0.1756、X1 0.1669、L32 0.1703 食料/体·tick でほぼ同じ（−3〜5%）だが、総摂取は F 230、X1 262、L32 276 食料/tick で +14〜20%、窓の間に立っている食料の総量は F 7,285、X1 5,340、L32 4,329。再生は「満杯でないセルに 10 tick ごと 1」なので、セルを満杯まで放置しない集団ほど世界の再生量が増える。Forager は視界で最も豊かなセルへ歩く（Move の決定が 51%）ので貧しい縁のセルは満杯で止まる。学習者は Move 37%、Rest 8%、足元の食料を採って（行 12/13/28/29 で Gather 10/10）すぐ食べる（行 14/15/30/31 で Consume 10/10）。X1 は Consume の決定が 28%（F 18%）で、在庫を持たずに食べる方向に重みが動いた。立っている食料と総摂取は事前登録した指標ではない（`summarize.py` の「事後」節）。
3. **回転が速い。** 出生/tick は F 1.41、X1 1.67、L32 2.44、L128 3.63 で、個体数/出生率 ≈ 平均寿命は F 929、X1 944、L32 664、L128 353 tick。Learner の窓では老衰死がほぼ 0（L32 で 27 件、L128 で 0 件）。
4. **加害死が Learner の死因の 43%（L32）/ 54%（L128）を占める。** Harm の決定割合は L32 で 0.58% と探索の床（0.625% × 隣接のある割合 ≈ 0.93）そのもので、貪欲には選ばれていない（P5d'）。それでも 1,600 体 × 0.58% ≈ 9.5 加害/tick、`harm_damage` 20（体力 100、飢えた個体はそれ以下）で約 1 死/tick になり、死因の第 2 位を探索だけで作る。ε = 5% の既定は、Phase 4 の制裁の前から世界を暴力的にしている（R6）。L128 は Harm の決定割合が 1.19%（床の 2 倍、4/10 シードで 0.0125 超）で、Harm が多数派の (seed, 行) が 999 のうち 12 ある。行が 4 倍で各行の訪問が薄く、白紙の Q（0）が負の真値を持つ行動群の中で楽観的な初期値になるため、訪問の薄い行では「まだ試していない / 下げられていない」行動が貪欲に選ばれる（α = 1/16 では加害 1 回で Q は約 1.5 単位しか下がらない）。
5. **Transfer が床を超えたのは分かち合いではない。** Transfer が多数派の行は L32 で (seed, 行) 7 件、すべて `adjacent = 1` かつ `food_in_sight = 0` の行（16、20、21）で、その行で多数派が占める割合は 0.10〜0.20（例: seed 0 の行 16 は 1,703 体中 transfer 281、rest 242、store 237、consume 221、未訪問 358）。食料が視界にない行は、23 パッチの世界では訪問が稀で、Rest（0）/ Signal（0）/ Store（0）/ Transfer（−1）/ Gather の不発（−2）/ Move（−3）の即時コスト差が小さい。整数 Q の切り捨て更新は TD 誤差が 1 報酬単位（固定小数点 16）未満のとき Q を動かさないので、Rest と Transfer（差 1 単位）の順序は学習で決まらない。床の定義も甘かった: 探索で Transfer / Harm を引いても隣接個体がいなければ Intent は Rest になるので、床は 0.625% × 隣接率であり、観測 0.58% はそれに合う。
6. **食料が視界にある 16 行は 10 シードで同じ方策に収束している**（事後の表）: 足元に食料・在庫なし → Gather（0.98〜1.00）、足元に食料・在庫あり → Consume（0.89〜1.00）、在庫あり・足元になし・隣接あり → Consume、隣接なし → Move（在庫を持って食料のあるセルへ行き、そこで食べる）、在庫なし・足元になし・隣接なし・空腹でない → Move（0.56）、**空腹・在庫なし・足元になし・隣接なし（行 9）→ Rest（10/10、0.46）**。最後は「飢えながら休む」で、D6 が死に終端の報酬を与えていないこと（餓死は −5 の連続としてしか学ばれない）、代謝が行動に依存しないこと、採集の競合負け（`LostContention`）で食料への移動の価値が下がることが候補。次の問い。
7. **Reflex の突然変異は中立な酔歩だけではない。** `hunger_permille` は 10/10 シードで 500 から下がった（20k: 283〜476、平均 389。50k: 99〜360、平均 206）。方向がそろっているので選択が働いている可能性があるが、同時に Consume の重みも動く（X1 は在庫なしでも Consume を 28% 選ぶ = 不発で無料）ので、しきい値の意味自体が変わっているかもしれない。機構は本実験では特定できない。
8. **L128 は 20,000 tick では L32 に届かない**（98% vs 124% of F）。白紙を埋める谷が深く（tick 200 に 76〜116 体）、窓でも加害死が過半。D6 の既定 32 行は、この設定では学習速度の面でも妥当。128 行が分解能の利得を出すかは、より長い tick か ε の小さい設定で見る必要がある。
9. Signal（Say）の決定が 4.7%（L32）あるのは、`signal_cost` 0 で Rest と報酬で区別がつかないため（P5f の事前登録どおり）。記号の意味は学んでいない。

### 限界（事後に分かったものを追加）

- 事前の限界（単一設定、報酬は自己エネルギーのみ、Signal 無料、交渉なし、個体数 ≠ 適応度、進化には短い、統計は記述のみ）はそのまま。
- `cz sweep` は Q 表の行ごとの**訪問回数**を記録しないので、「訪問の薄い行」は qpolicy の未訪問数と多数派の割合からの推定。
- 探索の床の事前定義（0.625%）は Rest への置換を見落としていた（上記 5）。
- `q_delta_window` は集団平均の表の差で、世代交代（窓に 15 世代分）と訪問の薄い行の揺れを分けられない。
- 同じ機械で別セッションが動いていたので tick/s は参考値（順位は 3-7 の計測と同じ: Forager > Reflex ≈ Learner）。

### 次の問い（EXP-003 以降の候補。決定は ADR で）

1. **死の終端報酬**（D6 で「EXP-002 の後に判断」と先送りした項目）: 負の終端報酬を与えた Learner で行 9 の Rest が消えるか、個体数と死因がどう変わるか。
2. **ε の格子**（0 / 10 / 50 / 100‰）と **`harm_cost` の格子**: 加害死 43% が探索由来なら ε で線形に下がるはず。製品のデモ世界の既定（R6「コストを高めに置く」）を決める材料。
3. **Reflex の `hunger_permille` の低下**の機構: `--mutate` だけの Forager（重みは固定、しきい値だけ進化）を腕に足せば、重みの進化と分けられる。
4. 立っている食料と総再生量を `cz sweep` の指標に足し（事後に series から計算した）、「集団が刈り取る」機構を事前登録して検証する。
5. 3-9c の UI で「fixed vs learning」を並べるときの見どころ: Learner の tick 100〜300 の谷と回復、Violence 死の多さ、Forager より多い個体数と少ない立っている食料。
