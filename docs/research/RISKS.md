# 研究上のリスクと対策

## R1. 事前定義した行動から、どこまで「創発」を検証できるか

**問題**: 行動集合・観測・DSL の文法はすべて設計者が決める。所有権に相当する行動（排除・制裁）を表現できる語彙を与えれば、所有権「らしき」現象は出やすくなる。表現力の空間そのものが事前分布になる。

**対策**
1. 主張の単位を「X が出現した」ではなく「条件 C のとき、ベースライン B と比べて指標 M が有意に変化した」に限定する。
2. 行動語彙は**汎用プリミティブ**（Move/Gather/Transfer/Attack/Signal/Propose…）に留め、"Own"・"Claim" のような制度名の行動を作らない。
3. 必須の帰無モデル: (a) ランダム方策、(b) 通信を無効化、(c) 記憶を無効化、(d) 制裁コスト無限大。制度指標が帰無モデルでも同程度に出るなら創発とは呼ばない。
4. 制度の判定は**行動履歴と規則運用ログから計算する操作的指標**で行う（例: 所有権指標 = 「最初に資源へ到達/投資した個体以外の採取が、制裁確率の上昇と結びつき、かつ時間とともに減る」）。LLM による解釈を証拠にしない。
5. 指標・閾値・比較条件を実験前に `docs/research/experiments/` へ固定（事前登録）。

## R2. 決定論的再実行と並列化の両立

**対策（実装済み）**: Decide を純関数化 → 順序保存の並列 map。乱数は座標関数。Apply は単一スレッド・固定フェーズ。整数演算のみ。`parallel_decide_matches_serial` テストで bit 一致を検証。

**残課題**
- Apply の並列化（10 万体超で律速になりうる）: 空間を固定タイルに分割し、タイル内競合のみを並列解決、タイル跨ぎは決定論的な二段階で処理。必要と**計測で**示されるまで行わない。
- 認知層が浮動小数点を使う場合: Intent をイベント台帳に記録し、再生は記録から行う（ADR-0003）。
- 現在の 100k 体ベンチで serial 2.26 ms → parallel decide 1.28 ms。Apply 側の比率は未計測（プロファイル TODO）。

## R3. エージェント数増加時の性能劣化

**現状の計測**（docs/STATUS.md）: 1 体あたりの step コストは 1k→100k で約 21 ns → 37 ns に増加（キャッシュミスと推定、未プロファイル）。

**対策候補（計測で必要と示されてから実施）**
- Gather 請求のソートをセル単位のバケットに置換（O(n log n) → O(n)）。
- エージェントの空間インデックス（Phase 3 で他者観測を入れる時点で必須）: 一様グリッドバケット、tick ごと再構築。
- 視界走査のコスト: 半径 r で O(r²)。r を上げる実験では資源の積分画像/占有ビットマップを検討。
- エージェントを位置順に定期ソートしてキャッシュ局所性を改善（ただし正準順序は id 順を保つため、別インデックスで）。

## R4. エージェントの行動と世界の状態遷移の分離

**対策（実装済み）**: `Observation`（読み取り専用ビュー）→ `Intent`（行動 + 記憶更新）→ カーネルが適用。方策は世界を直接変更できない。`Failure` は物理的不能のみ。

**Phase 4 への含意**: 制度は「物理法則」を変えず、(a) エージェントの観測に規範情報を加える、(b) 制裁などの行動を他者に起こさせる、の 2 経路でのみ作用する。カーネルに「禁止された行動を実行不能にする」仕組みは入れない。

## R5. 将来の制度 DSL に備えて今抽象化すべきもの

今やるもの（最小）:
- **行動の結果を構造化して残すこと**: `TickReport` は集計のみ。Phase 2 のイベント台帳で `(tick, agent, intent, outcome)` を記録する。規範の違反判定はこの台帳の上で行う。
- **エンティティ ID の永続性**: 実装済み（再利用しない単調増加 id）。契約の当事者参照に必要。
- **行動語彙の拡張点**: `Action` enum に Transfer / Signal を追加できる形を維持。

今やらないもの: Institution 型、規範インタプリタ、合意プロトコル。必要な形は Phase 3 の通信・交渉実験の結果で決める。

## R6. Phase 3 で加わるリスク（ADR-0013）

- **加害行動の退化均衡**: `Harm` を入れると、学習が「殴り合って絶滅」や「最強者の独占」に収束しうる。結果として記録し、デモの既定ではコストを高めに置く。制裁として機能するかは Phase 4 の制度次第。
- **報酬ハッキング**: Learner の報酬は自己エネルギーのみ。移転は損なので分かち合いは出ない想定。出ないことを失敗と扱わない（Phase 4 の前提条件）。
- **解釈可能性**: 方策の内部が見えなくなる。インスペクタに重みの要約・Q の上位行動を出し、台帳の相互作用から行動を説明できる形を保つ。
- **スナップショットの肥大**: 記憶と Q 表で数倍になる。巻き戻し時間を再計測し、間隔を調整する。

## R7. その他の指摘

- **人口動態のパラメータ依存**: 出生（エネルギー分裂）と寿命は ADR-0008 で導入し、既定設定では 10 シードすべてが約 1,250〜1,365 体の帯域に収束した（EXP-001）。ただし帯域の位置も収束の有無も、再生量・代謝・出生閾値という設計者の選択で決まる。制度の実験では、人口が帯域に入っている区間だけを分析対象にし、帯域外（絶滅・爆発）の設定は別扱いにする。
- **Forager 方策は設計者知識そのもの**: Phase 3 では学習方策と比較し、Forager は上界参照としてのみ使う。
- **H4（因果）の範囲**: 介入効果はモデル内部の因果効果であり、現実社会への一般化は別論点。報告時に必ず区別する。
- **乱数品質**: SplitMix64 の統計検定は未実施（ADR-0004）。
