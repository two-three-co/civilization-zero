# ADR-0002: Decide / Apply の二相 tick と固定フェーズ順序

- 状態: 採用 (2026-10-17)

## 文脈
行動の実行順が結果に影響する（同じ食料を複数体が取る等）。また将来の認知層を世界の物理から分離したい。

## 決定
1. **Decide**: 全エージェントが `S(t)` の読み取り専用ビュー（`Observation`）から `Intent` を返す。純関数で、世界を変更できない（記憶の更新も `Intent` で返す）。
2. **Apply**: Consume → Gather → Move → Upkeep → Death → Environment の固定順で適用。
3. Gather は**移動前の位置**で解決する（同時手番セマンティクス）。同一セルの請求者は `(cell, 抽選キー)` でソートし、在庫が尽きるまで逐次配分。抽選キーは `RngStream(seed, tick, agent, GatherPriority)`。
4. Move は同時適用。Phase 1 はセル容量無制限なので移動衝突は存在しない。

## 理由
- Decide を純関数にすると、並列化しても結果が変わらない（`parallel_decide_matches_serial` で検証）。
- 「id が小さい方が勝つ」等の固定優先は系統的な不公平を生み、所有権の創発研究にバイアスを入れる。抽選は seed で再現可能かつ公平。
- 行動種別ごとのフェーズ分けにより、エージェント処理順への依存が無い。

## 代替案
- 逐次（エージェント順に即時適用）: 実装は容易だが順序依存で並列化できない。却下。
- 比例配分: 整数の端数処理規則が必要で、Phase 1 では抽選で十分。将来の介入実験の対象にはなり得る。

## 帰結
- 1 tick 1 行動。行動の複合（移動しながら採集）は不可。
- 将来セル容量や移動の衝突を入れる場合、Move に専用の衝突解決（同じく抽選）を追加する。
