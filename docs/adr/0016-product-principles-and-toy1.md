# ADR-0016: 製品原則 A〜F と Toy 1 の再定義、Toy 1 優先への計画見直し

- 状態: 採用 (2026-10-18)。製品オーナーの指示（2026-10-18 のマスタープロンプト追補）に基づく。矛盾する部分はこの ADR と docs/PRODUCT.md が優先する
- 前提: docs/PRODUCT.md（2026-10-18 改定）、ADR-0010（Toy 1 = Phase 2 の旧定義）、ADR-0012（再生と fork）、ADR-0015（Phase 5 の設計。本 ADR で保留）

## 文脈

Phase 1〜4 は完了し、Phase 5（Research Platform）は 5-1 / 5-2 まで実装した。
2026-10-18 に製品オーナーが製品の理念・遊び方を固定しないこと・Toy 1 の 5 番目の操作・設計原則 A〜F を定めた（docs/PRODUCT.md）。
点検（同日、コード変更なし）の結果は次のとおり。

- 満たす: A（native と wasm の両ビルド、CI の wasm = native 照合）、D（LLM 不使用、文はテンプレート、実験の「読み」は判定と分離）、F（Phase 1〜4 のデモ）、出生・寿命・Store / Transfer、GitHub と CI。
- 部分的: B（再現の材料は揃うが「初期状態 + シード + 介入ログ」の 1 ファイル形式とマルチプレイの検討記録がない）、C（台帳は当事者と一部の原因を持つが、決定の理由と分岐 A / B の差の経路を辿れない）、E（カーネルの語彙は汎用だが、画面は "encroachment" "accused" "sanction" "promise" "rule" "charter" など人間の法制度の語彙）。
- 未: **Toy 1 の操作 5「なぜ違いが生まれたかを辿れる」**。Phase 2 の「Toy 1 完了」は旧定義の 1〜4 に対する判定。
- 計画の衝突: ADR-0015 は実験ダッシュボードという研究者向けの遊び方に寄り、5-3〜5-9 を Toy 1 の完成より先に置いていた（原則 3「遊び方を固定しない」と Toy 1 優先に反する）。

## 決定

### D1. 製品原則 A〜F を採用する

docs/PRODUCT.md の 5 を正とする。要約: **A** 実行環境を固定しない / **B** 歴史は「初期状態 + シード + 介入ログ」から再現でき共有可能な単位 / **C** 台帳は原因を辿れる情報を残す / **D** 事実と解釈を分ける（LLM は語りに限定） / **E** 人間社会のラベルを自動付与しない（命名は人間の役割） / **F** 完了条件はオーナーが触るデモ。

### D2. Toy 1 を 5 操作で再定義し、完了条件を「説明できること」にする

Toy 1 = ブラウザで (1) 観察 (2) 任意の時点に巻き戻す (3) 介入する (4) 分岐と元の世界を並べて比較する (5) **なぜ違いが生まれたかを辿れる**。
**完了条件（T6）: 製品オーナーが説明を受けずにブラウザで 5 操作を行い、分岐した世界がなぜ違ったのかを自分の言葉で説明できる。** 説明できなかった場合は、どこで理解が止まったかを一緒に確認して改善し、再判定する。
各タスクの完了時には、ブラウザで確認できる URL と「何を見ればいいか」を報告する。

### D3. Toy 1 完成までの最短経路: T1 → T4 → T2 → T3 → T5 → T6

順序は製品オーナーの指定（T2 のパネルの文言を最初から中立的な語彙で作るため、T4 を T2 の前に置く）。

### D4. Phase 5 の残り（5-3〜5-14）と Phase 6 は保留

ADR-0015 の 5-3〜5-14（信用割当、H2 の軸、適応的立法者、EXP-005〜008、ダッシュボード、計測、文書）と Phase 6（Genesis）は Toy 1 の完成後、製品オーナーが遊び方を決めてから ADR-0015 を改定して再開する。5-1（`cz-lab`）と 5-2（個体追跡）は済で、T1 の計測器としても使う。

### D5. T4 の語彙の条件

「正確さ」と「読みやすさ」を両立させる。人間社会の制度名（所有権、封建制、通貨、法、罰、契約…）は使わない。操作的な記述が長すぎて読めなくなるのも避ける。短く・具体的で・非エンジニアが一読でわかる表現にする。迷う箇所は言い換え案を複数並べて製品オーナーに見せる（docs/VOCABULARY.md）。研究用の内部名（`NormKind::Encroach`、指標 E / S′ など）は研究文書と CSV に残す。

### D6. マルチプレイの検討事項（原則 B。今は実装しない）

- 歴史の単位（T3）が共有の単位になる。複数人が同じ世界に介入する形は 2 通り: (a) 同じ原点から各自が fork する（歴史ツリー。衝突なし。決定論で誰でも再現できる）、(b) 同じ分岐に複数人が順に介入する（介入ログに介入者を記録する必要がある。順序の決定はサーバーか合意の仕組みが要る）。
- (a) は静的配信のまま可能（単位の交換だけ）。(b) はサーバーかピア同期が要る（原則 A はこれを排除しない）。
- 介入者の識別子を介入ログに持たせるかは、形式の版上げで後から足せる（`History.format` を上げる）。今の `Intervention` には入れない。
- 判断は Toy 1 の後、遊び方を決めるときに行う。

### D7. リポジトリの公開設定（製品オーナーの判断待ち。push は保留）

2026-10-18 の調査結果（詳細は STATUS「配信」）: リポジトリは User アカウント `two-three-co` の public リポジトリで、GitHub Pages（workflow 方式、public）と Actions（ubuntu、ci ≈ 3〜4 分 / run、pages ≈ 1 分 / run。直近 2 日で ci 41 回・pages 33 回）で動いている。
private に切り替えた場合: GitHub Free では Pages が使えず公開デモは停止する（Pro / Team なら継続するが、Pages の URL は private リポジトリでも**公開のまま**。アクセス制限は Enterprise のみ）。Actions は動くが private リポジトリでは月の無料枠（Free 2,000 分、Pro 3,000 分）を消費し、現在の頻度（≈ 85 分/日）では Free の枠を超える。代替: (1) ソースを private にし、ビルド成果物だけを別の public リポジトリの Pages に配信、(2) Cloudflare Pages / Netlify / Vercel に `dist/` を配信（Cloudflare Access なら無料でメール認証のかかった非公開デモにできる）、(3) public のまま。判断までは push を保留し、切り替えも行わない。

## 却下した / 先送りした案

- Toy 1 完成前に 5-3 以降を進める（研究者向けの遊び方への固定になる）。
- 画面の語彙を内部名のままにする（原則 E に反する）。
- 理由コードを状態やハッシュに入れる（ゴールデンが変わる。opt-in の材料で足りる）。
- LLM による「なぜ」の説明文（原則 D。T2 は事実のリンクだけで作り、語りは入れない）。

## リスク

- 「なぜ」の経路は、介入直後の最初の分岐は明快でも、数百 tick 後の差は無数の小さな分岐の累積になる。T2 は「最初の分岐」と「差の広がりの曲線」を中心に見せ、後半の差を 1 つの原因に帰さない（帰すと D に反する）。
- 語彙の中立化で読みやすさが落ちる（D5 で両立を条件にし、オーナーが選ぶ）。
- 理由コードの追加で `Intent` が大きくなり decide が遅くなる（opt-in、≤ 3% を門に）。
