### 性能に関する注意（正直な記録）

2026-10-18（4-9a）: 同じバイナリ・同じ target で規則ありの decide 4 本を続けて 3 回計測すると、コードに触れていない盲目の変種も含めて run ごとに 4〜10% 動き（`reflex_evolved_rules_blind` 224 → 233 → 219 ns など）、1 本だけが 1 run で +22% 暴れることもあった（`learner128_rules` 228 → 251 → 320 → 292 → 214.9（2.23〜2.28 ms、静か）、同じ run の盲目の対照は 218〜220 のまま）。criterion の change は run 内の標本の比較なので、この動きも「regressed」と出る。以後、decide の門の判定は、同じ run の対照（盲目の変種）が記録値から動いていない静かな run の値で行い、1 run の数字で改定・最適化を決めない（4-9a の行と ADR-0014 D6 の「決定」）。

Phase 1 初版で報告した 12.8 ns/体·tick は、出生前の 610 体がパッチ上で採集している tick 200 の状態での値だった。
定常帯域では個体の多くが食料を探して視界（半径 4 = 41 セル）を走査しており、`policy::decide` が実行時間の 78%（`docs/perf/2026-10-17-decide-before.svg`）。
ADR-0011 で走査を行スライス化（ハッシュ不変、-16%）→ 2 パス分岐なし化（ハッシュ変更、-19%）し、累積で step 194 → 132 µs/tick。
切り分け（視界 0 の世界との差）では走査が decide の 84% を占めていた。ADR-0011 後も decide が 72.5%（`docs/perf/2026-10-17-decide-after.svg`）で、残りの主な候補は `apply` の採集請求ソート（約 7%）。
